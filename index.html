01 / THE SIMPLE VERSION

Less history.
More headroom.

Old runs are useful until they aren’t. gh-cleaner gives your repository a clear, reviewable way to retire stale Actions history and the artifacts attached to it.

02 / BUILT-IN GUARDRAILS

Deletion with
a paper trail.

Destructive commands should be boring. Every decision is visible, constrained, and yours to approve.

⌁

Nothing goes
behind your back.

The core workflow uses visible gh api -X DELETE commands — no third-party action hiding the important part.

A / AUDITABLE
◎

Dry-run
is the default.

Scheduled executions preview only. Destructive mode requires an explicit manual choice and a safety cap.

B / CONTROLLED
◌

The recipe
stays untouched.

Workflow files, branches, releases, issues, pull requests, source code, and in-progress runs are never deleted.

03 / GET MOVING

One copy.
One commit.

Copy the workflow into your repository, commit it to the default branch, then open Actions and run your first preview.

Get gh-cleaner on GitHub ↗
terminal
# copy the workflow
cp .github/workflows/cleanup.yml \
  ../your-repo/.github/workflows/

# preview before deleting
DRY_RUN=true gh-cleaner \
  --repo owner/name \
  --older-than 30d
